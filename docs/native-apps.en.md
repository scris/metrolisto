# iOS / Android native app development

English | [简体中文](native-apps.zh.md)

MetroListo uses Capacitor 8.5.2 to package the existing React app for iOS and Android. Both platforms share the web source code, city data and routing logic.

## Project configuration

| Item                              | Configuration                                                                 |
| --------------------------------- | ----------------------------------------------------------------------------- |
| App name                          | 全地铁                                                                        |
| iOS Bundle Identifier             | `com.tianzeds.ml`                                                             |
| Android applicationId / namespace | `com.tianzeds.ml`                                                             |
| Configuration file                | `capacitor.config.ts`                                                         |
| Web build output                  | `dist/`                                                                       |
| iOS project                       | `ios/App/App.xcodeproj`                                                       |
| iOS dependency management         | Swift Package Manager; Capacitor maintains `ios/App/CapApp-SPM/Package.swift` |
| Minimum iOS version               | 15.0                                                                          |
| Android project                   | `android/`                                                                    |
| Minimum Android API               | 24 (Android 7.0)                                                              |
| Android compileSdk / targetSdk    | 36                                                                            |

The app loads bundled web assets, with no development server URL in the configuration. iOS uses automatic content insets to respect system safe areas; Android uses Capacitor’s system bar handling. The map, journey records and city data can also load offline.

## Local environment

- Node.js 22+ and pnpm 12.8.1.
- iOS: macOS, Xcode 26+ and the corresponding iOS SDK. The project includes Capacitor 8.5’s `SceneDelegate` and UIScene configuration for use with Xcode 27. CocoaPods is not required.
- Android: Android Studio 2025.2.1+, JDK 21, Android SDK Platform 36 and any build tools requested by Android Studio. You can use Android Studio’s bundled JDK.

Opening the Xcode project for the first time requires internet access to resolve Swift Package Manager dependencies. Opening the Android project for the first time requires internet access to download Gradle and Maven dependencies. Store the local Android SDK path in `android/local.properties` and do not commit it.

References: [Capacitor environment requirements](https://capacitorjs.com/docs/getting-started/environment-setup), [Swift Package Manager](https://capacitorjs.com/docs/ios/spm), and [Capacitor 8.5 UIScene changes](https://capacitorjs.com/docs/updating/8-5).

## Development workflow

After checking out the repository, install dependencies and sync the web build:

```sh
pnpm install
pnpm build && pnpm sync:capacitor
```

For subsequent work, build as needed and open the project in the IDE:

```sh
pnpm build:ios
pnpm build:android
```

Both commands rebuild the web app and sync both platforms; they do not launch an IDE automatically. Afterwards, open `ios/App/App.xcodeproj` in Xcode or `android/` in Android Studio. If the web build is already up to date, you can sync just one platform:

```sh
pnpm exec cap sync ios
pnpm exec cap sync android
```

Continue to use `pnpm dev` for web debugging. After changing web code, Capacitor configuration or plugins, sync before rebuilding the native project. If you only change native Swift / Java code, build directly in the corresponding IDE.

`ios/` and `android/` are version-controlled native projects. Do not repeatedly run `cap add` during routine development or delete them as if they were web build output. Web assets, bridge configuration and Cordova compatibility directories generated by `cap sync`, along with build caches and user IDE settings, are ignored. A fresh checkout must run the sync step.

## Building and signing

- iOS: select your development team in the App target’s Signing & Capabilities tab in Xcode. Configure signing, version numbers and release settings as needed, then build or Archive.
- Android: build in Android Studio, or run `./gradlew assembleDebug` from `android/`. For a release, configure your own signing key and generate an AAB.

The project retains the Capacitor template icons and launch screens. Replace them according to the project’s visual guidelines before release. Do not commit signing certificates, keys or local machine paths.

## Data and validation scope

Journey history still uses localStorage, inside the installed app’s WebView. It is separate from data in Safari, Chrome or the web development server. Uninstalling the app or clearing its data deletes local journey records.

Backup export uses [Filesystem](https://capacitorjs.com/docs/apis/filesystem) to write UTF-8 JSON to the app cache, then [Share](https://capacitorjs.com/docs/apis/share) to open the system share sheet, where the user chooses a save location or receiving app. Cancellation and failure do not report a successful export. Android has a cache FileProvider configured. On iOS, `PrivacyInfo.xcprivacy` declares `NSPrivacyAccessedAPICategoryFileTimestamp` with the officially recommended reason code `C617.1` for accessing timestamps of the app’s own files. This is the Apple privacy manifest required by the Filesystem plugin; it does not request additional permissions or enable uploads. The system may reclaim cached files, so users must save a backup outside the app through the share sheet. The web app continues to use browser downloads, and import continues to use a file picker. Native file selection, saving through the share sheet and re-import must be tested on real devices before release.

Basic project checks:

```sh
pnpm test
pnpm format:check
pnpm build && pnpm sync:capacitor
```

`pnpm build && pnpm sync:capacitor` validates the TypeScript / web build, asset copying and platform configuration sync. It does not compile Swift / Java, install on a device or run a simulator.
